# 产品需求书：界面架构（精简版）

- **主题**：机器人仿真软件界面架构
- **版本**：v0.1
- **状态**：已实施（v1.3.0，2026-09-16；设备树的**动态时序**部分仍未做，见 §6）
- **创建日期**：2026-09-11
- **来源**：《机器人仿真软件界面架构（精简版）》

## 1. 背景与问题

首发推广阶段，界面承载了过多能力（左侧 4 个标签页 + 子标签页、右侧固定属性面板、占位区块、置灰按钮），
新用户首次打开时认知负担过重，难以在短时间内完成"建模 → 仿真 → 出代码"的闭环。

同时，代码预览、导出、时序等**输出类**功能被放在左侧，与"输出区应在右侧"的行业惯例相悖。

## 2. 目标

单窗口一体化布局，无多余弹窗切换；适配"工业现场 PLC 主控 + 子程序调试"的核心场景。

- 建模、仿真、编逻辑、出代码**全程无跨软件切换**
- 默认**子程序模式**，贴合 PLC 主控调用逻辑，规避全量代码杂乱

## 3. 整体布局

四大模块：左侧双 Tab 资源区、中间 3D 仿真区、右侧功能标签区、底部状态栏。

```
┌──────────────────┬──────────────┬──────────────────────┐
│ 场景设备库│设备树 │  3D 主视窗    │ 属性│代码预览│导出打包 │
└──────────────────┴──────────────┴──────────────────────┘
```

- **场景设备库**：从 eCatalog 挑机器人/组件拖入场景（原「资源库」）
- **设备树**：编排设备父子层级；把夹爪拖到机器人节点＝装夹到法兰（坐标系自动吸合）

## 4. 功能需求

### 4.1 左侧：资源库（快速建模区）

| 需求 | 优先级 | 说明 |
|---|---|---|
| 机器库 | P0 | 内置机器人、抓手、相机、治具、工位基座等标准设备模型，支持拖拽入场景 |
| 零件库 | P1 | 存放加工工件、结构件 3D 模型，支持自定义导入（✅ v1.3.3：零件库 JSON `orolp.parts/1` 参数化基本体导入，网格件走 URDF/厂商 CAD 通路） |
| 预置场景库 | P2 | 内置分拣工位等行业预制模板，一键加载（✅ v1.3.3：分拣工位 / 机床上下料 / 抓取工作站随 `assets/cells/` 提供，「载入预置工作站」一键列） |
| 可视化拖拽 | P0 | 设备卡片拖入 3D 视口即加入场景 |
| 静态从属绑定 | P2 | 设备／工件静态从属关系（法兰挂抓手、工位固定料框等） |

### 4.2 中间：3D 主视窗（核心仿真编辑区）

| 需求 | 优先级 | 说明 |
|---|---|---|
| 场景编辑 | P0 | 自由调整设备、工件空间位姿，可视化标记运动轨迹、取放工艺点位 |
| 动态仿真 | P1 | 支持运行、暂停、单步调试，预览运动时序、工位联动、节拍效率 |
| 联动交互 | P2 | 点击设备／动作高亮关联代码、IO 信号；可悬浮查看 PLC 链路逻辑 |
| 模式支持 | P2 | 兼容位置控制、力控模式仿真预览 |

### 4.3 右侧：可折叠多功能标签页（核心输出区）

所有标签支持折叠，按需展开，界面无冗余信息。

| 标签 | 优先级 | 说明 |
|---|---|---|
| 设备树 | P1 | 静态绑定：**拖拽调整**设备父子挂载关系（挂到机器人＝装夹到法兰，坐标系自动吸合）；动态时序：配置工序触发、信号等待、子程序调用 |
| 代码预览 | P0 | 默认视图＝机器人工位**子程序**（隐藏冗余主程序）；切换视图＝PLC 代码，自动匹配 FB 功能块、DB 块 IO 地址映射；支持 3D 动作与代码块双向跳转定位 |
| 导出打包 | P0 | 一键导出机器人子程序程序包、PLC 适配代码包、上位机通讯数据包（预留扩展） |

### 4.4 底部：状态栏

| 需求 | 优先级 | 说明 |
|---|---|---|
| 常驻信息 | P1 | 实时展示仿真节拍、碰撞检测结果、IO 状态、设备报错、运行日志 |

## 5. 核心产品特性

1. **现场优先**：默认子程序模式，贴合 PLC 主控调用逻辑
2. **极简操作**：一体化窗口，全程无跨软件切换
3. **双向兼容**：底层预埋上位机主控架构，支持后续迭代扩展

> 「空占位」半边由后者钉住——v1.3.1 把「工艺时序（泳道图）」从空壳换成真 `SequenceEditor`，六条至此全过。

- [x] 左侧仅一个「资源库」，不再堆叠多个标签页 —— 左侧只有一个 `QTabWidget` 容器（双 Tab），不再有并列的多个标签页
- [x] 左侧为双 Tab：场景设备库 / 设备树；右侧为可折叠标签：属性 / 代码预览 / 导出打包
- [x] 代码预览与导出打包位于右侧（「路径示教 / 硬件列表 / PLC 程序逻辑 / 机器人子程序」四个子标签随之一并搬入，能力不减）
- [x] 原「场景」标签页不再单独存在（改名为「设备树」，与「场景设备库」并列于左侧）
- [x] 任一标签页内容在小窗口下不被裁切（可滚动）—— 修复前实测：「场景设备库」最小内容高度 **286px** > 最小窗口下的可视高度 **267px**（底部「刷新」与拖拽提示被裁）；套上滚动容器后降到 **88px**
- [x] 界面无空占位区块、无置灰不可用的按钮 —— **按钮部分已过**（并修掉「一键导出…」被错误置灰：它自身文档写着"不要求先点生成代码"，却要等用户先点一次「生成代码」才亮）；**空占位部分 v1.3.1 已过**：「工艺时序（泳道图）」不再是骨架——换成了真 `SequenceEditor`（工步表 + 自绘泳道画布 + 四种工步对话框 + 校验/保存/载入，信号下拉取自真实点表 ∪ 握手信号），底层 `orolp.sequence` 提供序列模型与机器人/PLC 双出口
