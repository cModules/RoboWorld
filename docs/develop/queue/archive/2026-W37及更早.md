### 来源：core 收窄为纯硬件加速层（2026-09-26 第三轮，ADR-007）

- [x] **`core/` 只留硬件加速；i18n / features / render 各归其位**（口径："core 中只放硬件加速
  代码，包括 GPU、C++ 实现等"）。落点全部按 **AST 实测的真实消费者**定，不按感觉：
  - `i18n`(1538) → **新建 `support/`**：被 domain 5 / service 7 / adapter 8 处真实 import，
    放任何一层都会反向依赖 → 只能做并列于各层的最底层（守护 **H8**：不得 import 任何层）。
  - `features`(293) → `app/features.py`：真实消费者只有 `main.py` · `app/cli.py` ·
    `app/views/program_panel.py`（+ 已迁走的 GUI 债务面板）——"界面功能展示开关"本就属 App。
  - `core/render/`(1881) → `adapter/robot_library/{urdf_model,mesh,primitives}.py`：
    `primitives`（几何原语 + STL 写出＝模型构建）的消费者**只有** robot_library；`urdf_model`
    （URDF 加载）与 `urdf_builder` 同族，**顺带消掉"core 解析 URDF / adapter 构建 URDF"的双通路**；
    `mesh`（`MeshData` 容器）被两者共用，必须跟 primitives 走（否则 adapter 反向 import app）。
    **渲染代码本来就在 app**（`GLWidget` + `app/views/robot_renderer.py`），`core/render/` 里
    **一行 OpenGL 都没有**——它只是 GPU 数据的 CPU 侧准备。
  - `core/` 现状 = `src/`（C++）+ `__init__.py`（唯一 C++ 边界 + 过渡态兼容门面）。
    **守护 H7 白名单**：`core/` 下出现任何其它 `.py` 判硬违规（防杂项回潮）。
  - 旧写法 `core.i18n` / `core.features` / `core.render` **下线**：报错直接给新地址
    （`_MOVED_MODULES`），不静默转发（转发只会让人以为还是老结构）。

- [x] **门禁与配套同步**：guard 新增 H7/H8（含**反向验证**：塞违规文件即判硬违规，已钉进

### 来源：目录重整：`models/` → `assets/models/`（2026-09-26，方案 A）

- [x] **模型库并入 `assets/`，与 `assets/cells/` 平级**。理由：`assets/` 已是"非代码资源根"
  （`assets/cells/` 预置工作站 + `assets/vendor/` 生成物），`examples/assets/` 也已存在同一约定；
  合并后 `assets/{cells, models, vendor}` 三者同构，且 `app.spec` 的 `datas` 由两条（`models` + `assets`）
  **收敛为一条 `assets`**（冻结包体积不变——models 本来就整目录打包）。

- [x] **顺带核实并更正了一个流传已久的错误认知**：`.gitattributes` 里 `models/**/*.stl` 的 LFS
  规则**从未真正接管**这些文件——1041 个 STL 一直以**普通 git 对象**入库
  （`git lfs ls-files --all` = 0；索引 blob 与磁盘同体积，例 `ur16e/link_5_00.stl` 的 blob
  `b36a8ab…` = 9684 字节）。**因此搬迁顺序必须反过来**：先 `git mv`（此时新路径不匹配任何
  LFS 规则，纯重命名）→ 再处置规则。若先把规则指到 `assets/models/**`，git 会把工作树按
  clean filter 算出指针（实测 `hash-object --path=` 得 `721354f1…` ≠ 索引的 `b36a8ab…`）→
  1041 个 STL 立刻判"已修改"，任一次 `git add` 都把真内容换成约 130 字节指针，而 LFS 服务端
  并无这些对象 → **新克隆检出坏指针 = 丢数据**。故规则改为**注释保留**并在 `.gitattributes`
  写明原因与启用方式（`git lfs migrate import`，需重写历史，单独决策）。

- [x] **搬迁结果**：`git mv` 后 **1088 个文件被识别为重命名（`R`）**（抽样
  `R models/abb/irb1200/irb1200.urdf -> assets/models/abb/irb1200/irb1200.urdf`），
  历史里不会多出 40MB 副本；样本 blob 哈希前后一致（`b36a8ab…`）证明**未触发 LFS 过滤器**。
