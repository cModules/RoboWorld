# PRD：抓取工作站编辑、PLC 联调与交付导出

---

- **主题**：RoboWorld MVP 抓取工作站编辑与交付闭环
- **版本**：v0.1
- **状态**：草稿
- **创建日期**：2026-09-27
- **负责人**：待确定

## 1. 背景与问题

RoboWorld 当前已经具备部分抓取工作站能力，但主要以“载入预置文件”或“抓取工作站一键演示”的方式呈现。用户可以看到场景、机器人轨迹和部分回放结果，却难以按照自己的工位需求完成以下工作：

1. 从空白或模板建立一个可编辑的工作站；
2. 在场景中添加、删除、移动机器人、工件、夹具、传感器和 PLC 等设备；
3. 明确指定“哪个机器人使用哪个工具抓取哪个工件”；
4. 快速记录抓取点和放置点，并自动生成接近、提升、撤离等安全点；
5. 修改点位、运动类型、速度和工艺语义后重新校验；
6. 编辑设备清单与 IO 地址，使机器人程序和 PLC 控制逻辑使用同一份信号契约；
7. 一次性导出机器人程序、PLC SCL、IO 点表、工程文件和校验结果，形成可交付的调试包。

当前代码中已经存在部分底层能力：

- `assets/cells/` 预置工作站；
- `build_grasping_workstation()` 抓取工作站模板；
- `ProgramPanel` 抓取向导、轨迹编辑、校验和机器人后处理器导出；
- `service.plc_scl` SCL 工步生成与 IO 点表注释；
- `PathCodeEditor` 的硬件列表、IO 映射和 PLC 预览实现。

但其中 `hardware_list`、`plc_logic` 等功能在 MVP 默认配置中仍被隐藏，且机器人代码、PLC 代码、设备配置和交付文件尚未形成清晰的一体化操作流程。用户因此难以发现和使用已有能力，导出的结果也不能直接表达完整的现场调试交付内容。

如果不解决该问题，MVP 只能展示“预置演示”，不能让用户以较低学习成本完成“搭建工位 → 生成抓取程序 → 配置 PLC → 校验 → 导出交付”的核心闭环。

## 2. 目标

- **目标 1：** 用户从模板或空白工作站开始，在单窗口内完成场景编辑、抓取程序编辑、PLC IO 配置和交付导出，不需要切换外部软件。
- **目标 2：** 首次使用用户在不阅读源码的情况下，能够在 10 分钟内完成一个抓取点、一个放置点，并生成可预览的机器人程序和 PLC SCL 模板。
- **目标 3：** 机器人程序、抓取/放置语义、夹爪 IO、PLC 工步和 IO 点表使用同一份数据来源，避免两侧逻辑不一致。
- **目标 4：** 导出操作能够生成明确的文件清单，并在导出前报告未映射 IO、缺少机器人模型、程序校验失败等问题。
- **目标 5：** MVP 默认入口能够让用户发现上述能力，同时保持未完成的真机上传、插件生态和高级时序功能隐藏。

### 2.1 非目标（本次不做）

- 不实现真实机器人控制器的在线上传、回读和现场闭环验证；
- 不实现 PLC 真机连接、在线下载或 TIA Portal 自动通信；
- 不承诺生成的 SCL 未经现场配置即可直接下装；
- 不实现力控、视觉闭环、手眼标定和自动路径规划；
- 不实现完整的泳道式工艺时序编辑器（保留现有基础能力，后续单独迭代）；
- 不新增厂商品牌分支，机器人代码继续使用现有后处理器注册表；
- 不在本需求中重写 `ProgramPanel`、`PathCodeEditor` 或 `GLWidget`，超限文件按“一次一个职责”逐步拆分；
- 不通过 GUI 直接修改 Domain 原生对象，跨模块数据使用 Service 接口和 DTO。

## 3. 目标用户与场景

| 用户角色 | 典型场景 | 核心诉求 |
|---|---|---|
| 离线编程工程师 | 根据工位布局建立机器人抓取和放置路径 | 快速示教、编辑、校验并生成机器人代码 |
| 自动化/电气工程师 | 配置传感器、夹具、PLC 和机器人握手信号 | 编辑 IO 地址，确认输入输出方向和等待条件 |
| 系统集成商 | 将一个工位交付给现场调试人员 | 一次导出机器人程序、PLC 模板、IO 点表和工程文件 |
| 方案演示/售前人员 | 用标准抓取工作站展示软件能力 | 一键建立可编辑的示例，而不是只能播放固定演示 |
| 现场调试人员 | 根据校验结果修改点位和 IO 映射 | 快速定位错误、修改后重校验、查看交付文件清单 |

## 4. 功能需求

### 4.1 工作站创建与场景编辑

| 需求 | 优先级（P0/P1/P2） | 说明 |
|---|---|---|
| 从抓取工作站模板新建 | P0 | 创建机器人、工具、输送设备、工件、托盘等基础对象，并进入可编辑状态 |
| 从预置文件载入工作站 | P0 | 继续支持 `assets/cells/*.json`，载入后场景、对象关系和工程数据可继续编辑 |
| 创建空白工作站 | P1 | 创建空场景并允许用户从场景设备库添加对象 |
| 场景设备库 | P0 | 机器人、工具、工件、夹具、传感器和工作台等设备支持拖拽或双击加入场景 |
| 设备树 | P0 | 展示对象层级、机器人与工具挂载关系、工件归属和当前选中对象 |
| 属性编辑 | P0 | 编辑名称、位置、姿态、尺寸、挂载关系等可编辑属性；角度在 UI 中以度显示，内部以弧度保存 |
| 场景操作反馈 | P0 | 添加、删除、挂载、移动失败时显示原因和用户下一步操作，禁止静默失败 |
| 工程保存/加载 | P0 | 场景、设备、程序、点位语义、工件绑定、设备清单和 IO 映射写入 `.core` 并可恢复 |

### 4.2 抓取程序快速生成

| 需求 | 优先级（P0/P1/P2） | 说明 |
|---|---|---|
| 选择机器人 | P0 | 多机器人场景中明确当前编辑和生成程序所属的机器人 |
| 选择工具和工件 | P0 | 明确使用哪个末端工具抓取哪个场景对象；工件选择不得只依赖当前选中对象的隐式状态 |
| 记录抓取点 | P0 | 从当前机器人位姿记录抓取点，并标记为 `PICK` |
| 记录放置点 | P0 | 从当前机器人位姿记录放置点，并标记为 `PLACE` |
| 抓取向导 | P0 | 根据抓取点、放置点和用户输入的高度参数生成接近、提升、撤离点 |
| 工艺语义编辑 | P0 | 支持 `APPROACH`、`PICK`、`LIFT`、`PLACE`、`RETRACT`、`VIA` 等点位语义 |
| 路点编辑 | P0 | 插入、删除、编辑位姿、修改运动类型、上移、下移，并保持语义与点位同步 |
| 运动参数编辑 | P1 | 编辑速度、运动类型和必要的工艺参数，单位明确显示 |
| 程序预览 | P0 | 显示点位、运动指令、夹爪动作和当前机器人归属；支持从问题定位到对应点位 |
| 自动生成夹爪指令 | P0 | `PICK/PLACE` 语义自动映射为夹紧/松开动作，回放和代码生成使用同一份语义 |
| 程序校验与节拍 | P0 | 校验可达性、关节限制、奇异、碰撞和点位语义，并显示节拍估算 |
| 回放验证 | P0 | 支持运行、暂停、单步、停止和工件吸附/释放随动 |

### 4.3 设备清单与 PLC IO 配置

| 需求 | 优先级（P0/P1/P2） | 说明 |
|---|---|---|
| MVP 开放硬件列表 | P0 | 将 `hardware_list` 从 MVP 隐藏清单移除，并在界面提供明确入口 |
| 编辑设备清单 | P0 | 添加、删除、修改设备名称、类型、厂商、型号、通信方式和 IP |
| 从场景同步设备 | P0 | 根据场景中的机器人、夹具、传感器和组件补齐设备清单，已有配置保留 |
| IO 映射编辑 | P0 | 编辑信号与地址的映射，显示信号方向、用途、设备归属和当前使用情况 |
| IO 自动编号 | P1 | 按信号方向为未映射信号生成候选地址，跳过已占用地址 |
| IO 校验 | P0 | 报告未映射、地址重复、方向冲突、程序使用但无设备提供等问题 |
| MVP 开放 PLC 程序逻辑 | P0 | 将 `plc_logic` 从 MVP 隐藏清单移除，并在代码预览或导出区域提供入口 |
| 根据机器人程序推导 PLC 工步 | P0 | 从 `SetDO`、`WaitDI`、`WaitTime` 等指令生成 PLC 工步，不能使用与实际程序无关的固定演示骨架冒充结果 |
| PLC SCL 预览 | P0 | 生成包含安全联锁、步序、等待条件、延时和 IO 点表注释的 SCL 文本 |
| PLC 生成结果提示 | P0 | 明确标识未映射地址和“生成物需现场验证”的风险，不得让用户误认为可直接下装 |

| IO 点表导出 | P0 | 导出 CSV 或 JSON 格式的设备、信号、地址、方向和用途清单 |
| 工程文件导出 | P0 | 导出当前 `.core` 工程，包含场景、程序、设备、IO 和校验所需数据 |
| 校验报告导出 | P0 | 导出人可读文本或 JSON 报告，包含错误、警告、节拍和未映射 IO |
| 统一交付包 | P0 | 选择目标目录后一次生成机器人程序、PLC、IO 点表、工程文件和报告 |
| 文件清单预览 | P0 | 导出前展示将生成的文件、跳过的文件及跳过原因 |

| 需求 | 优先级（P0/P1/P2） | 说明 |
|---|---|---|
| MVP 快速流程提示 | P0 | 在相关面板显示“建工位 → 选机器人/工件 → 记录点 → 生成 → 校验 → 导出”的步骤提示 |

## 5. 非功能需求

- **架构**：新 GUI 代码只能放在 `app/`；抓取、PLC、交付包业务逻辑放在 `service/`；Domain 不依赖 GUI；跨模块通信使用接口和 DTO。
- **扩展性**：机器人品牌代码继续使用 `adapter/post` 注册表；控制器接口继续使用 `controller_link` 协议；不得在交付导出窗口中硬编码品牌分支。
- **数据一致性**：机器人程序、点位语义、夹爪动作、PLC 工步和 IO 点表必须来源一致；修改后需重新校验。
- **单位**：角度内部统一弧度，GUI 输入/显示使用明确的 `*_deg` 转换；长度使用 mm，速度使用 mm/s。
- **性能**：普通工作站（不超过 4 台机器人、100 个场景对象、每台 200 个示教点）打开、编辑和切换面板不出现明显阻塞；导出过程中界面必须显示进度或状态。
- **兼容性**：保留现有 `.core` 文件读取能力；旧工程缺少设备、IO 或 PLC 段时应提示并使用安全默认值，不得静默丢失已有场景和程序。
- **安全性**：导出前明确提示机器人代码和 SCL 是工程模板或未经真机验证的结果；不提供未验证的在线下装入口。
- **可测试性**：Service 侧导出和校验逻辑可脱离 Qt 单测；GUI 侧覆盖入口、空态、错误定位和导出清单。
- **文件规模**：新增 GUI 组件不超过 300 行，新增 Service 文件不超过 400 行，新增 DTO 文件不超过 200 行；不得继续向已超过 600 行的债务文件堆叠新业务。

## 6. 验收标准

### 6.1 场景与程序编辑

- [ ] MVP 默认启动后可以看到并进入“硬件列表”和“PLC 程序逻辑”，无需设置 `CORE_FEATURES=full`。
- [ ] 用户可以从抓取工作站模板创建场景，并在设备树/属性面板中修改至少一个设备属性。
- [ ] 用户可以选择机器人、工具和工件，并明确看到当前选择关系。
- [ ] 用户记录一个抓取点和一个放置点后，界面显示对应语义。
- [ ] 用户通过抓取向导生成接近、提升、撤离点，生成点数量和点位顺序可见。
- [ ] 用户编辑一个点位或运动类型后，程序预览、回放和导出结果使用修改后的数据。
- [ ] 程序校验失败时能够定位到对应机器人、点位或程序行，并给出下一步建议。
- [ ] 回放时工件在 `PICK` 后跟随机器人，在 `PLACE` 后释放到场景。

### 6.2 PLC 与 IO

- [ ] 用户可以添加或修改 PLC、夹具、传感器和机器人设备。
- [ ] 用户可以为至少一个信号编辑 IO 地址，并在 IO 表中看到方向、用途和设备归属。
- [ ] 未映射、重复或冲突地址可以被 IO 校验明确报告。
- [ ] 抓取程序包含夹紧/松开动作时，PLC 工步由实际程序推导，不使用无关的固定演示步骤。
- [ ] PLC 预览包含安全联锁、步序、等待信号、延时和 IO 点表注释。
- [ ] PLC 生成结果明确显示“下装前必须核对地址与工艺步骤”的提示。

### 6.3 交付导出

- [ ] 用户可以在一个导出操作中选择目标目录并预览文件清单。
- [ ] 成功导出至少包含：机器人程序、PLC SCL、IO 点表、`.core` 工程文件和校验报告。
- [ ] 多机器人场景下，每台机器人生成独立且归属正确的程序文件。
- [ ] 导出文件名包含工位名、版本或时间戳中的至少一项，默认不覆盖已有文件。
- [ ] 导出失败时显示具体文件和原因，并且不显示“全部导出成功”。
- [ ] 重新打开导出的 `.core` 后，场景、点位语义、工件绑定、设备清单和 IO 映射保持一致。

### 6.4 质量与架构

- [ ] 新增功能入口注册在 `app/features.py` 的 `ALL_FEATURES`，并通过 MVP/full 两种档位测试。
- [ ] 新增用户可见字符串均通过 `support.i18n.tr()`，中英文词条完整。
- [ ] `python3 tools/check_arch_rules.py` 退出码为 0，不能新增硬性架构违规。
- [ ] 新增 Service、DTO、GUI 和交付导出测试覆盖正常、空态、错误和兼容旧工程路径。
- [ ] `pytest tests/` 全部通过；GUI 手动验证路径记录在发布说明中。

## 7. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 现有 `ProgramPanel`、`PathCodeEditor` 超过文件规模上限 | 继续开发会增加维护和回归风险 | 新增交付逻辑放入独立 Service/DTO/App 组件，债务文件只做必要接线和拆分 |
| `CellConfig`、场景数据和工程文件当前分散 | 保存/加载后设备或 IO 配置可能丢失 | 先定义工程快照/DTO，增加 `.core` 往返测试，再接入 GUI |
| PLC SCL 未经真实 TIA/PLC 验证 | 现场下装失败或安全风险 | 导出文件写入明确警告；MVP 只承诺模板和静态校验，不承诺在线下装 |
| 机器人程序与 PLC 工步语义不一致 | 机器人等待不到信号或夹具动作错误 | PLC 工步从实际机器人程序 IO 指令推导，并共享 `HANDSHAKE_SIGNALS` 和 IO 校验 |
| 多机器人点位和工件归属混淆 | 导出错误程序或错误抓取对象 | 所有程序、DTO、信号和工程段携带机器人名；增加多机器人回归测试 |
| 旧 `.core` 缺少新增段 | 打开旧工程失败 | 缺段安全降级并提示，不覆盖原有数据；新增兼容测试 |
| MVP 入口开放后暴露未完成能力 | 用户对产品能力产生误解 | 只开放硬件列表、PLC 编辑和交付模板；继续隐藏真机上传、插件和高级时序 |
| 无真实厂商 PLC 参数 | 地址和通信配置无法自动保证正确 | 地址由用户编辑，导出前强制 IO 校验和现场核对提示 |
| 交付目录覆盖已有文件 | 破坏现场已有版本 | 导出前确认，默认使用带版本/时间戳的新目录 |
| OpenGL/Qt 环境差异 | GUI 测试和实际启动结果不一致 | 保留无头结构测试，同时在 macOS/Windows 桌面环境执行手动启动和导出验证 |
