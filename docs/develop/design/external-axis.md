## 1. 两种模式先把概念钉住

| 模式 | 行话 | 变位机在焊接时 | 机器人侧 | 工程复杂度 |
|---|---|---|---|---|
| **分段定位** | position-weld | 每段焊前**停住**，把焊缝转到合适姿态 | 只在静止的工件坐标系里干活 | 低——变位机角度只是「分段参数」 |
| **联动焊接** | weld on the fly | 与机器人**同时**匀速运动 | TCP 沿焊缝走、姿态随变位机实时补偿 | 高——两套运动系统时间同步 |

真实现场大量使用分段定位（船型位置焊接本身就是「转到船型位再焊」），
联动多用于长直缝/环缝的连续焊接。**建议 P1 只做分段定位**，联动另立项。

## 2. 现状盘点（代码事实）

* `world/components.py`：`positioner_1axis`（回转）与 `positioner_2axis`
  （L 型，倾斜 @ 回转）已是**参数化静态几何**——`rot_deg`/`tilt_deg`
  变了台面与工件接口真的跟着转（变换顺序与真实机构一致）。缺的是
  「这个角度是会动的轴」这层语义。
* `world/scene.py`：对象支持 `parent` 挂载，但**只挂固定偏移**——没有
  「挂在一个会转的关节上」的概念；机器人是唯一带关节的实体。
* `planner.py` / `program.py`：`Trajectory`/`Waypoint`/`Motion` 全部只含
  机器人关节；程序指令集（movej/moveL/IO…）没有外部轴。
* `post/*`：8 个品牌后处理，**零外部轴语法**（E1、Group、MechUnit 等
  关键词一个都没出现——grep 过）。

## 3. 出码参考（各品牌外部轴语法形态）

| 品牌 | 外部轴形态 | 出码侧要点 | 落地判断 |
|---|---|---|---|
| **FANUC** | 独立运动组（Group 2…） | 位置数据带组掩码；变位机常配「联动系数」在系统侧配置 | 可做：J/P 行携带组信息 |
| **KUKA** | E1–E6 扩展轴（`$AXIS` / EX_AX） | `movej` 轴角度序列直接含 E1；`$VEL.EXAX` | 可做：最自然的嵌入方式 |
| **ABB** | Mechanical Unit（`MechUnitLoad` / `MechUnitMove`） | 机器人程序与 MechUnit 指令分开下发 | 可做：P1 出 `MechUnitMove` 行 |
| **UR** | **无外部轴概念** | 降级：变位机角度写注释 + 走数字量触发（现场 PLC 控制回转） | 诚实降级，不假装支持 |
| **estun / jaka / 汇川** | 多数支持扩展轴 | 具体语法**待厂商协议**（与 v0.2.3 同一阻塞口径） | TODO，不猜 |

## 4. 数据模型草案

**核心设计决策：外部轴位置进路点（`ext_joints`），不开新指令。**
理由：分段定位模式下「变位机角度」和「机器人关节角」一样是路径的自
变量——焊缝第 3 段在变位机 45° 时焊接，这个绑定关系天然属于路点；
开独立 `moveExternal` 指令反而把绑定关系拆散了。

```python
# 场景侧：对象带外部轴语义（挂在变位机 object 上）
ExternalAxisSpec(
    axis_type="rotary",        # rotary | linear
    home_deg=0.0,              # 起始角
    speed_deg_s=15.0,          # 占位示例，现场标定
    coupling_sign=+1,          # 联动方向（联动模式用）
)

# 程序侧：Waypoint 扩展
Waypoint(..., ext_joints=[45.0])   # None = 该点变位机不动
```

* **场景**：变位机 object 的 `params` 已有 `rot_deg`——ExternalAxisSpec
  复用它，几何层零改动（`_build_positioner_1axis` 已经按角度画）。
* **随动**：工件挂变位机台面（`parent` 已有）后，「按角度更新工件世界
  位姿」就是把现有固定偏移换成绕轴旋转的动态偏移——Scene 需要补一条
  「父对象带旋转关节」的位姿合成路径。
* **碰撞**：连杆-环境检查吃的是任意 object 世界位姿——位姿合成路径
  打通后**免费复用**，不需要新算法。

## 5. IK / 规划影响

* **P1（分段定位）不碰 IK**：变位机角度是给定输入，机器人在「工件动
  坐标系」里示教/求解——等价于把工件位姿换了个基，现有 `kinematics.py`
  原样可用。
* **P2（联动）是冗余求解问题**：6 + n 轴，焊缝速度由变位机与 TCP 共同
  决定，需要「先定变位机速度曲线 → 反解 TCP 速度 → 再解机器人」的
  分层策略。这就是 P2 另立项的主要原因。
* **节拍报表**：P1 里变位机转位时间是新增的可计算项（角度/速度，纯
  几何即可算），可进 ProgramReport——这是两段焊之间的定位等待，如实
  进时间轴，不与机器人动作重叠（联动模式的重叠留给 P2）。

## 6. GUI 影响面（P1 范围预估）

* 属性面板：选中变位机出现「外部轴」组（角度滑条 + Home + 速度）；
* 示教/轨迹编辑：路点列表加 ext 列（角度），编辑对话框加一栏；
* 程序面板校验：ext 越软限位报 error（复用既有 Issue 着色链路）；
* 场景树：挂载在变位机上的工件随角度实时刷新（依赖 §4 随动路径）。

## 7. 建议的分期立项

| 期 | 内容 | 依赖 | 预估规模 |
|---|---|---|---|
| **P1** | ExternalAxisSpec + 路点 ext_joints + 工件随动位姿合成 + KUKA/FANUC/ABB 原生出码（其余诚实降级）+ 定位时间进节拍 | 无外部依赖 | 一个完整开发循环轮（模型+出码+GUI+测试） |
| **P2** | 联动焊接（weld on the fly）：时间同步、冗余 IK、速度曲线对齐 | P1 + 用户拍板 | 数轮，建议独立立项 |

## 8. 开放问题（需用户拍板）

1. **品牌优先级**：P1 出码三品牌（KUKA/FANUC/ABB）的选择是否正确？
   若现场以某国产品牌为主，应先做它（语法待厂商协议，同 v0.2.3 阻塞）。
2. **机械参数来源**：变位机减速比/速度/限位——用户给数，还是等厂商包？
   文档里现在是占位示例，实施前必须换真值。
3. **P2 是否立项**：联动焊接的真实需求程度（若现场以分段定位为主，
   P2 可以无限期挂起）。
