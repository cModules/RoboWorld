## 1. 优先级分层（MoSCoW）

- **Must（必须，决定软件"能用"）**：碰撞检测、真机 CAD 接入、速度/节拍规划、GUI 轨迹编辑器
- **Should（应该有，决定"好用"）**：动力学/力矩校验、CAD/CAM 导入、IO 与工艺参数、标定导入
- **Could（可以有，决定"差异化"）**：多机协同、力控柔顺、点云、云协作、插件市场
- **Won't（本阶段不做）**：自研控制器固件、实时 Linux RT 内核、自研 CAD 内核

    - 第 11 条留下的"真机 `ControllerLink`"缺口的第一种形态：现场要连的控制器五花八门，共同点只有"有个网口"，因此把传输收敛成**一问一答的单行 JSON 行协议**（`core-socket` v1，常量 `SOCKET_API_VERSION`）。
    - 交付：`link.SocketLink`（`protocol="socket"`）——`connect()` 用 `socket.create_connection` + 握手协商（客户端自述 api 版本；**版本不等即拒**，避免"按错语义跑出错误轨迹"；服务端用 `caps` 声明 `programs`/`feedback`/`pose` 能力）；`upload_program`（代码走 base64，换行/中文注释/引号转义不再是问题）、`list_programs`、`fetch_program`（取回原文核对"上传的到底是不是我发的那份"）、`read_joints`、`set_joints(joints, at_time=)`（时刻原样过线，供服务端建模伺服滞后）、`get_pose`（优先问控制器，退而用本地正解）；`describe()`/`caps`/`dof`/`server_info`/`requests` 自省接口。
    - **失败语义刻意分两类**：网络/协议级故障（连不上、超时、乱码、对端撂断、响应缺 `ok`）→ 抛 `LinkError` **并把连接标记为未连接、关掉 socket**（把断掉的链路留在 `connected=True` 更坏）；服务端业务性拒绝（`ok:false`，例如程序名写错、关节数不符）→ 只抛异常、**不断会话**。
    - **能力如实**：握手说没有 `feedback` 就 `read_joints()` 返回 `None`，绝不用本机运动学伪造"实际位置"；回读的关节数与握手 `dof` 不符直接报错（一份没法用的数据不该悄悄传到偏差曲线上）。
