# 开发与维护

本目录面向所有开发参与者，统一管理从工程规范、产品需求到产品交付的资料。人工开发者与自动化开发代理使用同一套文档，不再单独设置人工或人工智能文档分类。

## 开发工作流

```text
路线图（Roadmap）/ 里程碑 → 产品需求（PRD）
→ 技术设计 / 开发计划 → 活跃队列 → 开发与验证
→ 验收归档 → 复盘回写
```

各阶段的关系如下：

1. **路线图与里程碑**：明确版本目标、优先级和交付节奏。
2. **产品需求（PRD）**：说明要做什么、为什么做、范围是什么，以及怎样算完成。
3. **技术设计与开发计划**：说明怎么做、采用什么方案、分几期实施，以及如何验证。
4. **活跃开发队列**：将已确认且可执行的任务按优先级排入当前工作队列。
5. **开发与验证**：完成编码、测试、架构检查和必要的文档更新。
6. **验收归档**：确认交付结果，将完成的计划、决策和验证记录归档。
7. **复盘回写**：根据实际结果修正路线图、产品需求和开发队列。

### 产品需求与开发计划约定

文档流转关系为：

```text
路线图 / 里程碑 → 产品需求（PRD）
→ 技术设计 / 开发计划 → 活跃队列 → 开发与验证
→ 验收归档 → 复盘回写
```

| 内容 | 正式位置 | 作用 |
|---|---|---|
| 产品需求书（PRD） | `prd/<英文短名>.md` | 定义用户问题、产品范围和验收标准 |
| 技术设计 | `design/<英文短名>.md` | 记录架构方案、技术取舍和设计决策 |
| 开发计划（Plan） | `design/<英文短名>.md` | 拆解任务、排期和实施验收方式 |
| 长期路线图（Roadmap） | `ROADMAP.md` | 管理版本方向、阶段目标和优先级 |
| 活跃任务队列 | `BUILD_QUEUE.md` | 管理当前开发顺序和执行状态 |
| 完成归档 | `queue/archive/` | 保存已完成任务、验证结果和决策记录 |

文件约定：

- 产品需求使用 `prd/<英文短名>.md` 命名。
- 技术设计和开发计划使用 `design/<英文短名>.md` 命名。
- 模板文件使用 `_TEMPLATE.md` 命名，并放在对应目录中。
- 一篇文档只讨论一个相对完整的主题，避免形成无法维护的大杂烩文档。
- 架构设计、技术方案和开发计划均属于设计决策资料，统一存放在 `design/`。架构总则与领域架构图位于本目录根部，作为全部设计资料的共同依据。

### 文档状态

所有产品需求、技术设计和开发计划统一使用以下状态：

- `草稿`：正在编写，内容可能发生较大变化。
- `评审中`：等待产品、技术或相关开发参与者确认。
- `已确认`：范围和方案已冻结，可以进入开发。
- `实施中`：已经进入开发或验证阶段。
- `已完成`：已经交付并完成验证。
- `已废弃`：不再执行，但保留文档以便追溯。

### 开发计划归档

开发计划由 CodeBuddy 生成在 `.codebuddy/plans/`。当计划中的所有待办事项（`todo`）都进入 `completed` 或 `cancelled` 状态后，运行：

```bash
python tools/archive_plans.py --dry-run
python tools/archive_plans.py
```

脚本会将已完成计划归档到 `design/`，并更新本页的开发计划索引；未完成计划继续保留在 `.codebuddy/plans/`。脚本可以重复执行：同名且内容一致的文件会跳过，同名但内容不同的文件会保留哈希后缀，绝不覆盖原文件。

## 文档组织

本项目尚未发布，不保留旧路径兼容入口。`develop/` 是所有开发参与者共同使用的文档体系，人工智能（AI）不单独占用文档分类。

文档职责边界如下：

- `ROADMAP.md`：先做什么，以及分几个阶段做。
- `prd/`：具体产品能力做什么，以及如何验收。
- `design/`：技术上怎么做，以及有哪些设计决策。
- `BUILD_QUEUE.md`：当前先做哪些任务。
- `queue/archive/`：已经完成了什么，以及过程中的验证和决策。

## 维护闭环

1. 从路线图与里程碑确认版本目标和优先级。
2. 将目标拆解为产品需求（PRD），明确用户问题、范围、验收标准和非目标。
3. 完成技术设计与开发计划，确认方案、风险、任务和验证方式。
4. 只将已确认且可执行的任务放入活跃开发队列。
5. 开发过程中同步完成测试、架构检查和必要的文档更新。
6. 完成功能验收后归档计划与决策，保留可追溯记录。
7. 将复盘结果回写到路线图、产品需求和开发队列，形成下一轮输入。
