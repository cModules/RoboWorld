# RoboWorld - 打包说明

> 打包相关文件已集中到 **`packaging/`**（P0-3 目录重整），本机脚本在 **`scripts/`**。
> 早先它们散在仓库根，与启动壳、文档混放。

## 快速开始

### 方法一：使用自动打包脚本（推荐，Windows）

```powershell
# 双击运行或在 PowerShell 中执行
.\packaging\build_win64.ps1
```

脚本自己会往上找到仓库根（`packaging/` 的上一级），产物仍落在仓库根的 `dist/`。

### 方法二：手动打包

```powershell
# 1. 激活虚拟环境（如果使用）
.venv\Scripts\Activate.ps1

# 2. 安装 PyInstaller
pip install pyinstaller pillow

# 3. 执行打包（在仓库根执行）
pyinstaller --clean packaging\app.spec
```

> `packaging/app.spec` 内部已把仓库根算成「SPECPATH 的上一级」，所以
> **在哪个目录敲这条命令都不影响**它找 `main.py` / `assets/models/` / `python/`。

## 打包配置

### app.spec 关键段（改动前请先读）

```python
_pkg_dir = os.path.dirname(os.path.abspath(SPEC))   # …/packaging
_repo_root = os.path.dirname(_pkg_dir)              # 仓库根

a = Analysis(
    [os.path.join(_repo_root, 'main.py')],
    pathex=[_repo_root, os.path.join(_repo_root, 'python')],   # 必须含 python/
    datas=[
        (os.path.join(_pkg_dir, 'logo.png'), '.'),
        (os.path.join(_repo_root, 'pyproject.toml'), '.'),     # features 清单真源
        (os.path.join(_repo_root, 'models'), 'models'),
        (os.path.join(_repo_root, 'examples'), 'examples'),
        (os.path.join(_repo_root, 'assets'), 'assets'),        # 预置工作站场景
        (os.path.join(_repo_root, 'README.md'), '.'),
    ],
    excludes=['tkinter', 'matplotlib', 'PIL', 'OCP', 'cadquery'],
)
```

注意：**所有路径都要显式挂到 `_repo_root` / `_pkg_dir` 之下**。spec 里写的相对路径
是按 spec 所在目录解析的——它现在在 `packaging/`，裸写 `'models'` 会指向
`packaging/models`（不存在），PyInstaller 不报错、只是**静默少打**。

## 常见问题

### Q: 打包后运行提示缺少模块？

A: 在 `hiddenimports` 列表中添加缺失的模块名称，重新打包。特别注意
五个顶层包（`core` 内核、`domain`、`service`、`adapter`、`app`，以及
`domain.world`、`adapter.robot_library`、`adapter.robot_library` 等子包）：
它们由 `main.py` 在 try/except 中导入，PyInstaller 的静态分析对"动态插进
`sys.path` 的包"不可靠，一律显式登记。

### Q: 本地 `python -m build` 打出的 wheel 里混进了早就删掉/搬走的模块？

A: 这是 **setuptools 复用 `build/lib/` 的增量复制**造成的：删掉或移动源文件后，
`build/lib/` 里的旧副本仍在，构建时被一并收进 wheel。**现象极隐蔽**——本地装包
一切正常，只是包里多出 `core/cli.py` 这类早已不存在的模块（2026-09-26 实测：
`wheel` 里的 `core/cli.py` 与 `build/lib/` 中的副本 md5 完全一致）。

**本地构建前先清干净**：

```bash
rm -rf build/ dist/ *.egg-info/
python -m build --wheel
```

CI 不受影响（每次从干净 checkout 构建），但**本地 wheel 校验必须先清 `build/` 才可信**。

### Q: 打包文件太大？

A: 可以在 `excludes` 列表中添加不需要的模块，减少文件大小。

### Q: 如何包含额外的数据文件？

A: 在 `datas` 列表中添加，格式为 `(源路径, 目标路径)`；源路径用
`os.path.join(_repo_root, ...)` 拼绝对路径。

### Q: 打包过程中提示图标格式错误？

A: 确保已安装 Pillow 库：`pip install pillow`，或者将图标转换为 .ico 格式。

## 安装器（三端文件关联）

绿色版 `dist/RoboWorld.exe` 拷到哪都能跑，但**没人替它告诉系统"`*.rwproj*` 归它打开"**：
双击工程文件会弹"你要如何打开这个文件"，用户眼里就是"装了软件却打不开工程"。
要"双击即打开"，必须走安装器。

三个后缀（`.rwproj` 主 / `.robotproj` 别名 / `.core` 历史兼容）的真源在
`service.project.PROJECT_EXTENSIONS`；应用身份、ProgID、UTI、MIME 的真源在
`app/app_identity.py`。三端安装器引用同一批常量，**由 `tests/test_installer.py`
静态守住**——这类配置写错不会让任何功能测试变红，只会在用户机器上表现为
"双击没反应"，所以只能静态守。

### Windows（Inno Setup）

```powershell
.\packaging\build_win64.ps1          # 1. 先产出 dist\RoboWorld.exe
.\packaging\build_installer_win.ps1  # 2. 再产出安装包（版本号自动取自 support.__version__）
```

产出 `dist\RoboWorld-Setup-<版本>.exe`。脚本需要 Inno Setup 6：

```powershell
winget install JRSoftware.InnoSetup.6   # 或 https://jrsoftware.org/isdl.php
```

关联写在 `HKA`（有管理员 → HKLM，否则 → HKCU），并设了 `ChangesAssociations=yes`
——**没有这一行，Windows 8 及以上不会采用新注册的文件关联**（沿用旧记忆，重装也没用）。
绿色版（不安装、直接拷目录）的自注册由 `app/platform_win.py` 在启动时写 HKCU 完成。

### macOS

```bash
./packaging/build_macos.sh   # 产出 dist/RoboWorld.app 与 dist/RoboWorld-macOS-<版本>-<arch>.dmg
```

文件关联由 `packaging/app.spec` 的 `Info.plist` 声明（`CFBundleDocumentTypes` +
`UTExportedTypeDeclarations`），脚本末尾用 `plutil` 校验它确实打进了包里。
脚本还会做 ad-hoc 签名——**未签名的 .app 会被 Gatekeeper 判为"已损坏"**；正式分发
要换成 Developer ID 签名 + notarize（脚本里有注释标注位置）。

### Linux

```bash
python -m PyInstaller -y packaging/app.spec   # 产出 dist/RoboWorld（无扩展名）
./packaging/linux/install.sh                  # 装到 ~/.local，无需 root
sudo ./packaging/linux/install.sh --prefix /usr
./packaging/linux/install.sh --uninstall
```

Linux 没有注册表，关联靠三处协作：MIME 定义（`share/mime/packages`）、桌面条目
（`share/applications` 里的 `MimeType`）、以及 `update-mime-database` /
`update-desktop-database`。**少任何一步都是"双击没反应"，而且不报错。**

### 验收清单（三端通用）

1. 双击 `.rwproj` 直接在本程序里打开（不再问"用什么打开"）；
2. 右键 → 打开方式里能看到 RoboWorld（Windows 靠 `Applications` 键，别漏了）；
3. 程序已在运行时双击工程 → 切到**已有窗口**，而不是再开一个（单实例）；
4. 老 `.core` 工程同样能双击打开；
5. 卸载后关联被清除（Windows 卸载项 / `--uninstall`）。

## macOS 打包（本仓库实测，2026-09-14 里程碑修正）

```bash
# 在仓库根目录执行（venv 里需先装 pyinstaller）
python -m PyInstaller -y packaging/app.spec
# 产出：dist/RoboWorld.app（66MB，arm64）+ dist/RoboWorld-macOS-<日期>.zip
cd dist && zip -qry RoboWorld-macOS-$(date +%Y%m%d).zip RoboWorld.app
```

### 四个踩过的坑（改动前请先读）

1. **`pathex` 必须包含 `python/`**
   `main.py` 运行时才把 `<repo>/python` 插进 `sys.path`，打包期 `pathex` 若不写
   `os.path.join(_repo_root, 'python')`，PyInstaller 解析不到 `core` 包。后果很隐蔽：
   应用能正常启动，但 `main.py` 里那一圈 `try/except: _HAS_XXX = False` 会**静默降级**，
   机器人库、场景建模、离线编程全部失效——"冒烟存活"不等于能用。
   验证方法：`grep -c "missing module named 'core" build/app/warn-app.txt` 应为 0；
   或直接查归档 `pyi-archive_viewer` / 读 `PYZ.pyz` 的 toc，应能看到全部 `core.*` 模块。

2. **spec 搬进 `packaging/` 后，仓库根要往上数一级**
   路径全走 `_repo_root`；照抄旧的 `os.path.dirname(SPEC)` 会把 `packaging/` 当仓库根，
   `assets/models/` / `examples/` / `python/` 全指空——同样是**静默少打**。
   这条已由 `tests/test_packaging_spec.py` 静态守住。

3. **`scipy` 不能放进 `excludes`**
   `domain/kinematics.py` 顶层无条件 `import scipy`，排除后打包版运动学全挂。

4. **`OCP` 必须放进 `excludes`**
   `service/cam.py` 在函数内部软依赖 `cadquery-ocp`，PyInstaller 会把 OCCT 内核
   （约 100MB 的 `.dylibs`）一起打进去，包体从 66MB 涨到 166MB。排除后
   CAD/CAM 相关函数会抛"未安装 cadquery-ocp"的友好错误，其余功能不受影响。

另外：**不要加 `--clean`**——它会触发沙箱的批量删除门禁（删 PyInstaller 缓存会被拦）。
`app.spec` 里已顺手过滤掉 `datas` 中的 `__pycache__`（整目录拷贝会把开发机的 `.pyc`、
甚至别的 Python 版本的 `.pyc` 一并塞进包）。

以上约束已被 `tests/test_packaging_spec.py` 固化为回归测试，改 `app.spec` 时测试会先报警。
